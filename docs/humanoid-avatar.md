# Bundled humanoid avatar

The studio includes `research-human-v2.glb`, an authored anatomical proxy with
textured skin, eyes, eyebrows, hair, clothing, teeth, and tongue. It supplies real
skinning and expression geometry for the existing face, speech, and measured
motion layers. Its shape sliders are design choices. No facial scan, fitted
likeness, or independent likeness assessment is claimed.

The procedural portrait remains available as a lightweight alternative and as
the fallback when a model cannot load. The known humanoid uses explicit rest-pose
calibration; uploaded models retain their own mapping and calibration workflow.

The optimizer checks that the full target-name set, nonzero target-name set, and
joint-name set survive packaging. Vertex and triangle counts are unchanged by
this run. Meshopt quantization and lossy WebP conversion mean numerical mesh
attributes and texture pixels are not asserted to be identical to the raw GLB.

Eye, hair, and brow materials use alpha masking at 0.35. The eye texture includes
a transparent layer over the iris; treating that material as opaque can obscure
the iris even when rig and geometry tests pass. The native asset test checks all
three material settings explicitly.

## Provenance

[Pinned input manifest](../tools/avatar/inputs.json) contains archive revisions,
archive hashes, and individual system-asset hashes. The graphical inputs are
published as CC0; MPFB's executable code is a separate GPL-3.0 build dependency.
The application ships the derived GLB and the
[CC0 text](../tools/avatar/LICENSE-CC0.txt), not the MPFB source tree.

| Input | Pinned source and role |
| --- | --- |
| Base human, rig, shape sliders, external build tool | [MPFB2 revision `6ff1eb3`](https://github.com/makehumancommunity/mpfb2/tree/6ff1eb358f6c1959ced77e79e6dd2406d9a71f49); see its [code/assets license split](https://github.com/makehumancommunity/mpfb2/blob/6ff1eb358f6c1959ced77e79e6dd2406d9a71f49/LICENSE.md) |
| Face and speech target geometry | [Extra targets revision `7eaba34`](https://github.com/makehumancommunity/extra-targets/tree/7eaba3453134385bb5ea9811ef0b33b85b4b556d), `faceunits01` and `visemes02`; [license](https://github.com/makehumancommunity/extra-targets/blob/7eaba3453134385bb5ea9811ef0b33b85b4b556d/LICENSE) |
| Textures and attached assets | [MakeHuman CC0 system-asset pack](https://files2.makehumancommunity.org/asset_packs/makehuman_system_assets/makehuman_system_assets_cc0.zip), 26 individually verified files |

The system pack was acquired with bounded HTTP byte ranges, per-member CRC32,
size, and SHA-256 checks. A digest of the entire 280,737,770-byte ZIP was not
claimed. Local verification also compares every extracted MPFB/extra-target
file against its pinned archive, so an edited extraction cannot silently serve
as a verified build input.

The upstream extra-targets README describes the expression/viseme sets as
autogenerated. Control availability and geometric movement therefore do not
establish production-quality expression anatomy or natural speech appearance.

## Rebuild

Blender 4.3.2 was used for the recorded export. Run from the repository root:

```bash
uv run python -m tools.avatar.fetch --output data/local/avatar-inputs
uv run python -m tools.avatar.fetch --output data/local/avatar-inputs --verify-only

blender --background --python tools/avatar/build.py -- \
  --inputs data/local/avatar-inputs \
  --output-dir reports/local/avatar-build --render

npm ci --prefix tools/avatar
node tools/avatar/optimize.mjs \
  reports/local/avatar-build/research-human-v2.glb \
  apps/web/public/models/research-human-v2.glb \
  tools/avatar/asset-report.json
```

`--verify-only` performs no downloads. The Blender builder requires already
verified inputs and records the macro/detail values it applies. Its optional
render and `.blend` output remain local review artifacts. Packaging dependencies
are pinned in the separate `tools/avatar/package-lock.json`; they are not part
of the web application's runtime dependency graph.

The build reproduces the asset construction and records resulting hashes;
byte-for-byte reproducibility across Blender/platform versions is not claimed.
When intentionally rebuilding the bundled binary, retain the corresponding
`build-report.json` and `asset-report.json` together.

## Runtime behavior

`GLTFLoader` uses the bundled Three.js Meshopt decoder. Textures and buffers are
embedded, so loading this asset does not contact a model CDN or fetch a decoder.
The model loader accepts same-origin URLs or local object URLs and enforces the
64 MiB model limit. Draco and KTX2 remain outside the supported decoder set.

`createResearchHumanMapping` applies the known model's yaw correction, relaxed
upper-arm/forearm offsets, and calibrated local bases. It restores the original
node transforms after inspection, leaving skin bind matrices intact. Joint
animation begins from the authored rest pose each frame. Explicit user mappings
can override this calibration; unrelated uploads do not inherit it by guesswork.

The renderer supports portrait and full-body framing. A framing change updates
the camera without reloading the model. Model changes abort obsolete downloads,
release old rig resources, and keep the existing procedural fallback behavior.

Native viseme blends suppress overlapping mouth/jaw morphs and jaw-bone opening,
preventing double articulation. Unsupported native blends retain the existing
face-channel fallback. Measured eye-direction morphs also take precedence over
duplicate gaze-bone rotations. Silence clears native speech weights back to the
neutral shape.

Measured source clips use their own recorded clock. The avatar's richer geometry
does not change a clip's review status or turn source-context retrieval into a
learned personal gesture policy. See [motion library](motion-library.md) for that
separate provenance and eligibility contract.

## Verification and limits

```bash
npm run typecheck
npm exec --workspace @bias/web -- vitest run src/avatar/native.integration.test.ts
npm run test:e2e
```

The native integration test reads the exact shipped GLB, verifies its SHA-256,
and decodes compressed geometry, morphs, and skin through `GLTFLoader` and the
real Meshopt decoder. It checks complete control binding, actual vertex movement
for eyelids/mouth/tongue, native speech and silence, relaxed arms, viewer-facing
orientation, and measured body deltas that move both joints and clothing. It also
checks that neutral returns do not accumulate deformation.

For these CPU tests only, image/material creation is replaced with plain
materials. The tests validate neither browser WebP decoding nor GPU rendering.
The browser suite covers the unmodified asset, successful GLB readiness,
portrait/body framing, and the procedural alternative on desktop and mobile.
[CI run 42943071040](https://github.com/Dindb-dong/who-is-your-bias/actions/runs/42943071040)
passed all 16 baseline browser cases at `3c10b3b`. Its actual desktop/mobile
screenshots were inspected: the textured human renders, full-body framing keeps
the feet in view, and measured-motion/calibration controls remain within their
panels. Static screenshots do not establish smooth animation or naturalness.
The local recovery environment rejected Chromium's process-singleton socket;
that failed launch supplied no rendering evidence. The current suite also
checks recovery after a failed GLB load; see [quality completion](quality-completion.md).

The recovered Blender preview demonstrates that the authored model can render,
but is not a screenshot of the web application. No independent likeness score,
expression-naturalness score, or perceptual motion evaluation has been recorded.
