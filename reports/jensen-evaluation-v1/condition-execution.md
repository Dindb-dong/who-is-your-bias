separate [execution contract](execution-contract.json) pins the new supervisor's
SHA-256, both existing v2 plan hashes, exact base/tokenizer hashes and CPU
float32/eight threads. Existing frozen implementation and plan files are
unchanged. Questions, factual selection, wording examples, reference isolation,
160 output tokens, seed 42 and 4,096-token context remain fixed.

## Run one condition

Wait for the shared model-memory slot. Run from the project root with the
prepared inference environment. The following commands are **proposed**, not
receipts of execution. Set `ART` to the restored artifact root and use new output
directories; existing attempts must never be overwritten.

```sh
EVAL_PLAN="$ART/text-evaluation-v1/frozen-v2/development/plan.json"
EVAL_CONTRACT="reports/jensen-evaluation-v1/execution-contract.json"
EVAL_OUTPUT="$ART/text-evaluation-v1/execution-development-v2"

PYTHONPATH=src:. .venv-inference/bin/python \
  -m tools.adaptation_evaluation.local_condition run \
  --condition facts --plan "$EVAL_PLAN" --contract "$EVAL_CONTRACT" \
  --dtype float32 --threads 8 --timeout 180 --output "$EVAL_OUTPUT/facts"
```

Inspect `supervisor.json`, `condition/run.json` and the server log, including
attempted/completed counts and any failure. The loop status `completed` does
not imply that every response completed successfully. A length finish reason
remains a failed response. Save the **whole directory**, including raw attempts,
private condition review, warmup, before/after health identity and launcher,
then freshly restore and compare its bytes before the next command.

```sh
PYTHONPATH=src:. .venv-inference/bin/python \
  -m tools.adaptation_evaluation.local_condition run \
  --condition style --plan "$EVAL_PLAN" --contract "$EVAL_CONTRACT" \
  --dtype float32 --threads 8 --timeout 180 --output "$EVAL_OUTPUT/style"
```

Save and freshly verify this condition too. The adapter command additionally
requires `EVAL_ADAPTER_SHA256` to be the actual file SHA-256 of the **completed**
training run's `run.json`. The existing validator checks its status, full
artifact manifest, training/base/tokenizer identity and the expected receipt
SHA before a server is started. Do not substitute a partial checkpoint.

```sh
PYTHONPATH=src:. .venv-inference/bin/python \
  -m tools.adaptation_evaluation.local_condition run \
  --condition adapter --plan "$EVAL_PLAN" --contract "$EVAL_CONTRACT" \
  --adapter-run "$ART/text-adapter-v1" --adapter-run-sha256 "$EVAL_ADAPTER_SHA256" \
  --dtype float32 --threads 8 --timeout 180 --output "$EVAL_OUTPUT/adapter"
```

For the six heldout cases, repeat this procedure with
`EVAL_PLAN="$ART/text-evaluation-v1/frozen-v2/heldout/plan.json"` and a distinct
`EVAL_OUTPUT="$ART/text-evaluation-v1/execution-heldout-v2"`. These heldout
plans use explicitly selected training evidence; this is a generation
comparison, not an end-to-end retrieval measurement.

The process terminates its server after each condition, with a kill fallback
for a server that does not terminate. On interruption it preserves any existing
partial condition report and raw generations; do not delete an unsuccessful
attempt. A server-start failure before any report exists is a failed preflight,
and cannot be collected as a condition result. An abrupt machine loss can
still require recovery from the runner's last per-case local checkpoint.

## Record verified persistence and collect

After uploading each complete directory archive, freshly materialize the
returned persistent object, verify the archive's byte count and SHA-256, unpack
it and compare **every file** with the source directory. Build the receipt's
`files_sha256` mapping from that freshly restored directory; include
`supervisor.json`. Record actual returned IDs, never example values. Private
source passages and generated answers remain in those artifacts, outside Git.

The receipt JSON has this shape, with exactly one entry for each condition:

```json
{
  "schema_version": "text-condition-durability.v1",
  "conditions": [
    {
      "condition": "facts",
      "plan_sha256": "the existing canonical plan hash",
      "status": "uploaded_and_fresh_readback_verified",
      "archive": {
        "file_id": "the returned file ID",
        "library_file_id": "the returned persistent file ID",
        "bytes": 123,
        "sha256": "the actual 64-character archive SHA-256"
      },
      "files_sha256": {
        "supervisor.json": "the actual file SHA-256",
        "condition/run.json": "the actual file SHA-256"
      }
    }
  ]
}
```

This schematic intentionally omits the other two entries and remaining files.
The collector rejects an incomplete receipt, missing files, pending upload or
readback, changed file hashes, changed supervisor seals, different runtime,
different plan or a server not marked stopped. It matches supplied verified
receipts to local bytes; it does not independently contact remote storage.

```sh
PYTHONPATH=src:. .venv-inference/bin/python \
  -m tools.adaptation_evaluation.local_condition collect \
  --plan "$EVAL_PLAN" --contract "$EVAL_CONTRACT" \
  --condition-directory "$EVAL_OUTPUT/facts" \
  --condition-directory "$EVAL_OUTPUT/style" \
  --condition-directory "$EVAL_OUTPUT/adapter" \
  --durability-receipts "$EVAL_OUTPUT/durability-receipts.json" \
  --output "$EVAL_OUTPUT/collection"
```

Collection calls the unchanged `compare_reports` and `export_review`. It saves
`comparison.json`, `review-summary.json` and a blind review packet. Keep the
private answer key separate from `blind-review/reviewer/`. Failed attempts stay
in the denominators and private failure record; they are not complete blind
samples. Human ratings remain ungraded and no efficacy claim follows from
transport completion. Save the resulting collection as another bounded output.

## Timing and validation limits

Each invocation starts one actual model server, so every condition has its own
excluded cold load and short warmup. The order is recorded by actual start time
and is not counterbalanced. Host load may differ between saved invocations.
The earlier single-process sequential method also had an order limitation;
this procedure does not establish unbiased latency or target-device speed.

The existing one-sentence, third-person, no-quotation constraints remain in the
Korean factual prompt, which limits the style contrast. Original earlier
speaker turns from the heldout source remain omitted. Judge factual support
and unresolved detail against supplied training evidence before interpreting
surface overlap or style.

Validation at this preparation checkpoint: 43 focused comparison/orchestration
tests passed, including 16 new tests for one-condition execution, exact model
identity rejection, virtualenv path preservation, partial-output retention,
cleanup and verified-receipt collection. Processes and HTTP are injected test
fixtures; these checks do not claim real model execution.
