# 첫 영상으로 실험하기

## 1. 실행 화면 열기

Mac에서는 이 폴더의 `시작.command`를 더블클릭한다. 이 컴퓨터에는 프로젝트 전용 환경에 필요한 패키지를 설치해두었다. 터미널에서 직접 실행하려면 다음과 같이 한다. 아래 명령은 모두 **이 프로젝트 폴더 안에서** 실행한다.

```bash
./시작.command
```

화면 주소는 `http://127.0.0.1:8501`이다. 외부에 공개하는 서버가 아니다. 종료할 때 실행한 터미널에서 Ctrl+C를 누른다. 포트가 사용 중이면 이미 실행한 화면을 쓰거나 명령의 `--server.port`를 바꾼다.

다른 컴퓨터에서 처음 설치한다면 Python 3.11 이상을 준비한다.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-asr.txt
.venv/bin/python -m pipeline doctor
```

자동 전사를 쓰지 않고 제공 자막만 처리한다면 `requirements.txt`로 설치할 수 있다. `requirements.lock.txt`에는 검증 당시 버전이 기록되어 있다. 다른 운영체제에서 GPU 패키지를 맞출 때는 설치 환경에 맞게 조정한다.

## Aside로 여러 영상 한꺼번에 처리하기

1. Aside를 열고 연결된 상태에서 이 폴더의 `시작.command`를 실행한다. 작업실이 이미 열려 있으면 페이지를 새로 고친다. 메뉴가 보이지 않으면 기존 실행을 종료한 뒤 다시 실행한다.
2. 왼쪽 **실제 자료 → Aside 일괄 수집**에서 검색어를 넣고 **Aside로 검색**을 누른다. 기본 검색어는 젠슨 황 영어 인터뷰다. 필요하면 채널 이름을 입력한다.
3. 처리할 후보를 선택한다. URL이 있다면 한 줄에 하나씩 직접 넣어도 된다. 같은 영상의 주소가 여러 개면 한 번만 처리한다. 음성 참조가 필요하면 **원본 영상 또는 음성도 확보**를 선택한다.
4. **선택한 영상 일괄 처리**를 누른다. 기본 설정은 Aside 자막을 우선 쓰고, 사용할 자막이 없으면 다운로드를 시도한다. 영상에서 자막을 확보하지 못하면 CPU로 자동 전사한다. 원본 확보 옵션을 켜면 처음부터 다운로드 경로를 사용한다.
5. **2. 전사·검수**에서 영상 제목으로 출처를 고른다. 화자, 원문, 문답 묶음, 타임스탬프를 확인한 뒤 검수 완료 표시를 하고 **3. 데이터셋**에서 새로 만든다.

자료는 프로젝트의 `data/local/sources/영상 제목 [yt-영상ID]/`에 저장한다. 제목이 없는 영상은 ID로 표시한다. 기존 폴더는 일괄 작업이 끝난 뒤 `시작.command`로 다시 실행할 때 제목이 있는 항목부터 정리한다.

선택한 영상과 진행 상태는 `data/local/batches/`에 저장된다. 중간에 종료되거나 실패한 항목은 작업 기록에서 골라 **미완료 항목 이어서 처리**를 누른다. 이미 검수표를 수정했다면 기존 작업을 보존한다.

`LLM_BASE_URL`과 `LLM_MODEL`을 `.env`에 설정하고 작업실을 다시 열면 **LLM으로 화자·문답·태그 초벌 제안**을 켤 수 있다. 이때 텍스트가 설정한 API로 전송된다. LLM 설정 없이도 자막·전사 수집은 작동하며 자막에 화자 이름이 명시된 구간에만 규칙으로 초벌 표시를 한다. 소리를 기준으로 화자를 구분하는 기능은 아직 없다. LLM은 60구간씩 처리하므로 묶음 경계에 걸친 문답도 검수할 때 확인한다.

일괄 수집은 검색용으로 등록하며, 영상 ID를 임시 촬영분 ID로 사용한다. 같은 인터뷰의 하이라이트와 원본을 검색용·평가용으로 나눠 쓰기 전에 동일 촬영분으로 정리한다. 실제 영상 다운로드가 차단되면 확보한 로컬 파일을 **1. 자료 입력**에서 등록할 수 있다.

## 2. 영상 또는 자막 등록

왼쪽 **실제 자료 → 1. 자료 입력**으로 이동한다.

1. `출처 ID`에 `jensen-interview-001`처럼 파일마다 다른 이름을 입력한다.
2. `원본 촬영분 ID`에 방송 단위 이름을 넣는다. 같은 방송에서 자른 파일들은 같은 값을 쓴다.
3. 검색에 쓸 영상은 `train`, 평가에만 쓸 다른 촬영분은 `eval`을 선택한다.
4. 영상/음성을 업로드한다. 큰 영상은 컴퓨터의 절대 경로를 입력해도 된다. 자막이 있으면 함께 넣는다.
5. 원문 언어와 출처·이용 범위 메모를 기록하고 **자료 등록**을 누른다.

유튜브 URL만 넣으면 한 영상과 해당 언어 자막을 내려받는 경로가 실행된다. 영상이나 자막 파일을 함께 넣었다면 URL은 출처 기록으로만 저장하며 다운로드하지 않는다. 채널 전체·재생목록은 입력할 수 없다. 접근 제한 영상은 확보한 로컬 파일로 넣는다.

유튜브 처리에 필요한 Deno를 새 컴퓨터에도 설치하려면 아래 명령을 실행한다. 공식 바이너리와 체크섬을 받아 프로젝트의 `.tools` 안에만 설치한다. 이 컴퓨터에서는 설치를 완료했다.

```bash
.venv/bin/python scripts/install_youtube_runtime.py
```

공개 영상에서 다운로드를 확인했다. 영상별 접근 제한이나 사이트 변경에 따라 실패할 수 있다. 그 경우 원본 파일로 입력하면 이후 단계는 같다. [yt-dlp 공식 안내](https://github.com/yt-dlp/yt-dlp) · [Deno 공식 설치 안내](https://docs.deno.com/runtime/getting_started/installation/)

## 3. 자동 전사와 사람 검수

**2. 전사·검수**에서 등록한 출처를 고른다. 자막이 있으면 검수표가 바로 보인다. 영상만 있으면 모델을 선택하고 자동 전사를 실행한다. 첫 실행은 모델 다운로드가 필요하다.

- 처음에는 `small`과 `cpu`를 기본값으로 제공한다. 간단한 연결 확인은 `tiny` 또는 `base`로 해볼 수 있다. 모델 크기에 따른 실제 인물 전사 품질은 별도 비교한다.
- 학교 NVIDIA GPU 환경을 받으면 그 환경에 설치한 뒤 `cuda`를 선택한다. 현재 Mac에서 cuda를 고르면 실행되지 않는다.
- 전사는 글자와 시간의 초벌 결과다. 자동 화자 분리는 구현하지 않았으며 화자는 `unknown`으로 시작한다. [faster-whisper 공식 사용법](https://github.com/SYSTRAN/faster-whisper)

예를 들어 질문 자막 2줄과 답변 4줄이 있으면 여섯 줄에 `turn_id=q001`을 붙이고 질문 두 줄은 `interviewer`, 답변 네 줄은 `target`으로 지정한다. 전사와 시간을 듣고 확인한 뒤 `reviewed`를 체크한다. 질문 없는 강연에는 `kind=style`을 사용한다.

참조 음성으로 쓸 구간은 **대상 혼자 말하고, 배경음이 적고, text가 원음과 일치할 때만** `voice_clean`을 체크한다. 자막과 맞춰 음성을 자르므로 문장 중간이 끊기지 않도록 시작·종료를 조정한다.

**검수표 저장**을 누른다. 엑셀에서 작업하려면 CSV를 내려받아 수정한 후 같은 화면에서 다시 가져온다. 전체 필드 설명은 [Data.md](Data.md)를 참고한다.

## 4. 데이터셋과 답변 실험

**3. 데이터셋 → 데이터셋 만들기**를 누른다. 완료 문답 수와 제외된 그룹을 확인한다. 오류가 나면 해당 출처의 검수표로 돌아가 수정한다. 검수표를 고친 뒤에는 데이터셋을 다시 만들어야 반영된다.

**4. 답변 실험**에서 데이터셋을 고르고 인물 카드를 편집한다. 처음 카드는 이름만 있고 말투 관찰은 비어 있다. 검수 자료에서 관찰한 말투와 근거 문답 ID를 함께 추가한다. 평가 자료를 근거로 쓰지 않는다.

- 질문을 직접 넣으면 그 질문 한 개를 A/B/C로 비교한다.
- 질문을 비워두면 eval의 모든 인터뷰 질문을 사용한다. 실제 정답은 모델 입력에 넣지 않는다.
- 상황은 질문을 받을 때 알 수 있는 맥락으로 적는다. C 조건 검색에 사용한다.
- 답변 언어를 영어/한국어 중 고른다. 영어 자료 검색은 영어 질문부터 시험한다.
- **A/B/C 실험 입력 만들기**만 누르면 API 비용 없이 검색 결과와 실제 프롬프트를 볼 수 있다.

외부 모델로 실제 답변까지 만들려면 `.env.example`을 `.env`로 복사하고 사용하는 서비스의 값을 적는다. 키를 문서나 카톡에 붙이지 않는다. base URL은 `/v1`처럼 채팅 API의 기준 주소여야 한다. 실제 호출 경로는 그 뒤에 `/chat/completions`가 붙는다.

```text
LLM_BASE_URL=https://사용할서비스의주소/v1
LLM_MODEL=사용할모델명
LLM_API_KEY=본인의키
```

설정 후 실행 화면을 재시작하고 **설정한 LLM으로 답변 생성**을 누른다. OpenAI 호환 Chat Completions 형식과 `temperature`를 받는 모델을 대상으로 한다. 다른 API 형식은 별도 어댑터가 필요하다. API 오류 시 성공한 결과를 저장한 뒤 중단하며 자동 재시도하지 않는다. 다시 누르면 새 실험 결과 폴더가 생기고 호출 비용이 다시 발생할 수 있다.

평가표는 조건을 가린 답변과 스타일·상황 반응·사실 정확도 항목을 제공한다. 실제 인터뷰 답변은 `references.DO_NOT_PROMPT.jsonl`에 별도로 저장된다. `blind_key.DO_NOT_SHARE.json`은 조건 대조용이며 평가자에게 같이 보내지 않는다.

## 5. 음성을 준비하고 동욱에게 넘기기

**5. 음성·인계**에서 `voice_clean`으로 확인한 검색용 음성 구간을 추출한다. 답변을 입력하거나 생성된 답변을 불러와 읽고 수정한다. 참조 음성을 선택하고 **동욱에게 넘길 묶음 만들기**를 누른다.

ElevenLabs를 쓰려면 다음을 `.env`에 설정하고 재시작한다.

```text
ELEVENLABS_API_KEY=본인의키
ELEVENLABS_VOICE_ID=이미사용가능한목소리ID
ELEVENLABS_MODEL_ID=eleven_multilingual_v2
```

**ElevenLabs로 음성 생성**을 누르면 실제 API 호출이 일어난다. 지금 구현은 기존 voice_id로 말하게 하는 기능이다. 젠슨 황 자료를 넣었다고 해당 목소리가 자동으로 ElevenLabs에 생성되는 것은 아니다.

Qwen/CosyVoice에서 만든 음성은 파일을 올린 뒤 **생성 음성 연결**을 누른다. `avatar_turn.json`의 상태가 `ready_for_video`이면 `speech.wav`와 자막을 영상 쪽에서 사용할 수 있다. 음성이 없는 `awaiting_audio` 묶음은 TTS 담당자에게 먼저 넘긴다. 자세한 규격은 [Handoff.md](Handoff.md)에 있다.

## 명령행으로 반복 실험하기

웹 화면과 같은 처리를 명령행에서도 실행할 수 있다.

```bash
# 로컬 영상+자막
.venv/bin/python -m pipeline ingest --source-id jensen-001 --recording-id interview-001 --media "/영상/절대경로.mp4" --subtitles "/자막/절대경로.srt" --split train

# 영상만 등록했다면
.venv/bin/python -m pipeline transcribe jensen-001 --model small --device cpu --language en

# 검수표를 화면 또는 CSV로 수정한 다음
.venv/bin/python -m pipeline review-import jensen-001 "/검수표/절대경로.csv"
.venv/bin/python -m pipeline build

# 인물 카드 생성 후 내용을 편집
.venv/bin/python -m pipeline init-card data/local/persona.json

# dataset-실행ID는 build가 출력한 실제 폴더로 변경
.venv/bin/python -m pipeline experiment --dataset "data/local/datasets/dataset-실행ID" --card data/local/persona.json --question "How should I handle a failed project?" --situation advice --language en --k 3

# 실제 LLM 호출. abc-실행ID를 experiment 결과로 변경
.venv/bin/python -m pipeline run-llm "data/local/experiments/abc-실행ID"

# 음성 참조, 인계, 선택적 TTS
.venv/bin/python -m pipeline reference jensen-001 seg-00002
.venv/bin/python -m pipeline handoff --text-file "/읽을답변.txt" --language en
.venv/bin/python -m pipeline tts "data/local/handoff/turn-실행ID"
```

`--root`로 별도 실험 폴더를 지정할 수 있다. 명령 앞에 둔다.

```bash
.venv/bin/python -m pipeline --root data/demo-new demo
.venv/bin/python -m unittest discover -s tests -v
```

## 자주 만날 상황

| 표시 | 대응 |
| --- | --- |
| 같은 출처 ID/원본 파일이 있음 | 같은 자료를 다시 등록하지 않고 기존 검수표를 이어서 수정 |
| 같은 촬영분을 검색/평가로 나눌 수 없음 | 재업로드도 같은 용도에 묶고 다른 촬영분을 평가용으로 준비 |
| 내보낼 검수 자료가 없음 | turn_id, speaker, reviewed 확인 |
| 질문과 답변이 겹침 | 자막 타임스탬프 조정, 새 질문부터 다른 turn_id 사용 |
| 자동 자막 내용이 반복됨 | 원음을 확인하고 중복 자막 행을 exclude로 표시 |
| 모델을 찾지 못함/전사 다운로드 실패 | 네트워크와 모델명 확인. 제공 자막으로 먼저 진행 가능 |
| API 401/429 등 | 키·모델 권한·한도 확인. 성공한 결과는 기존 실행 폴더에 남음 |
| 음성 API 후 변환 실패 | 저장된 provider_output.mp3를 생성 음성 연결로 다시 적용. API 재호출 불필요 |

키나 실제 자료 없이 확인한 범위는 [검증기록.md](검증기록.md)에 기록한다.
